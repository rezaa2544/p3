# راهنمای استقرار

## ۱. سه شکل استقرار

| شکل | مناسب برای | وضعیت در ۰.۱.۰ |
|---|---|---|
| سرور اینترنتی + PostgreSQL مدیریت‌شده | تولید واقعی مدرسه؛ دبیر از بیرون مدرسه وصل می‌شود | **همه‌ی اجزا ساخته و تست شده‌اند، اما استقرار واقعی انجام نشده (BLOCKED: میزبان/دامنه در دسترس نبود)** |
| نسخه‌ی ویندوزی تک‌فایل (`payesh2.exe`) | پایلوت روی رایانه‌ی مدرسه، نسخه‌ی پشتیبان، نمایش داخلی | ساخته شده و مسیر بوت/ورود آن روی همان بستر تست شده؛ اجرای آن روی ویندوز واقعی **NOT RUN** |
| اجرای مستقیم با Node از مخزن | توسعه، CI، تست | PASS (این بستر همین حالا همین‌طور اجرا می‌شود) |

> هشدار: نسخه‌ی ویندوزی برای «یک رایانه، یک مدرسه» طراحی شده. اگر رایانه‌ی مدرسه خاموش شود،
> سرویس قطع است؛ بنابراین **نقطه‌ی بحرانی میزبانی نباید رایانه‌ی مدرسه باشد** و برای تولید
> باید شکل اول (میزبان اینترنتی) استفاده شود.

## ۲. اجرای تولیدی با Node + PostgreSQL

```bash
# ۱) پیش‌نیاز: Node 22+ و PostgreSQL 15+
npm ci
npm run build                     # وب + API

# ۲) متغیرهای محیطی (حداقل‌ها)
export NODE_ENV=production
export DATABASE_URL='postgres://payesh:***@db-host:5432/payesh2?sslmode=require'
export SESSION_SECRET="$(openssl rand -base64 48)"   # ≥۳۲ نویسه، غیر پیش‌فرض
export COOKIE_SECURE=1
export APP_ORIGIN='https://payesh.example.ir'
export HOST=127.0.0.1 PORT=3000
export UPLOAD_DIR=/var/lib/payesh/uploads
export LOG_LEVEL=info

# ۳) مهاجرت و نخستین مدیر (رمز تصادفی یک‌بار چاپ می‌شود)
node apps/api/dist/scripts/migrate.js
node apps/api/dist/server.js        # با PAYESH_FIRST_ADMIN=1
```

- `NODE_ENV=production` سه محافظ دارد: `SESSION_SECRET` ضعیف/پیش‌فرض → خطا،
  `COOKIE_SECURE=0` → خطا، `SEED_DEMO=1` → خطا. داده‌ی نمونه هرگز در تولید اجرا نمی‌شود.
- سرو SPA از خود API انجام می‌شود (`WEB_DIST`)، بنابراین فقط یک پورت لازم است.
- پشت Nginx/Caddy قرار دهید و TLS را همان‌جا تمام کنید؛ `TRUST_PROXY=1` (پیش‌فرض) برای
  تشخیص IP صحیح است.
- `/api/health` برای healthcheck: `{"status":"ok","db":"ok","migrations":2}`.

## ۳. نسخه‌ی ویندوزی

```powershell
# روی ویندوز ۱۰/۱۱ (x64) — بدون نیاز به نصب Node
.\payesh2.exe
# سپس در مرورگر: http://localhost:3000
```

- در نخستین اجرا، رمز موقت مدیر در کنسول چاپ می‌شود (یک‌بار). آن را یادداشت و در نخستین
  ورود تغییر دهید.
- محل داده: `%USERPROFILE%\.payesh2\` (پایگاه داده PGlite، کلید نشست، آپلودها).
- متغیرهای قابل تنظیم: `PORT` (پیش‌فرض ۳۰۰۰)، `HOST` (پیش‌فرض `0.0.0.0` برای دسترسی
  دستگاه‌های دیگر شبکه‌ی مدرسه)، `PAYESH2_HOME`، `ADMIN_PASSWORD`، `FIRST_SCHOOL_NAME`.
- ساخت مجدد فایل اجرایی: `node scripts/build-exe.mjs --target win-x64` (خروجی در `artifacts/`).
- محدودیت صادقانه: فایل اجرایی امضای دیجیتال تجاری ندارد (هشدار SmartScreen ممکن است) و
  **روی ویندوز واقعی اجرا نشده است**؛ فقط مسیر بوت روی باینری لینوکسیِ همان بسته تست شده.

## ۴. پیکربندی حداقلی امن برای پایلوت اینترنتی

| مورد | توصیه |
|---|---|
| TLS | اجباری؛ کوکی `Secure` |
| پشتیبان | روزانه + نگه‌داری ۳۰ روز + آزمون بازیابی ماهانه |
| حساب مدیر | رمز قوی، تغییر رمز موقت، در فاز بعد MFA |
| شبکه | فقط ۴۴۳ عمومی؛ دیتابیس در شبکه‌ی خصوصی |
| لاگ | ارسال `LOG_LEVEL=info` به فایل/سرویس مرکزی؛ داده‌ی حساس در لاگ نوشته نمی‌شود |

## ۵. کارهایی که در این محیط انجام نشده

- استقرار روی یک میزبان عمومی با دامنه و TLS واقعی (**BLOCKED**: بدون دسترسی به سرویس
  میزبانی و دامنه).
- اجرای فایل اجرایی ویندوز روی ویندوز واقعی (**NOT RUN**).
- آزمون بار روی PostgreSQL مدیریت‌شده (فقط PGlite سنجیده شد).
