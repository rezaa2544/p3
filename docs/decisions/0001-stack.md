# ADR-0001: انتخاب پشته فناوری

- **وضعیت:** پذیرفته‌شده
- **تاریخ:** 2026-10-23

## زمینه

نیاز به یک سامانه مدرسه‌ای فارسی/راست‌چین با PWA، آفلاین مقاوم، کنترل دسترسی نقش‌محور،
بودجه عملیاتی پایین، و تیم کوچک. محدودیت محیط ساخت نیز واقعی است (بدون Docker/JDK).

## تصمیم

| لایه | انتخاب | دلیل |
|---|---|---|
| زبان | TypeScript در هر دو سمت | تایپ مشترک، کاهش خطای قرارداد API |
| Backend | Node.js 22 + Fastify 5 | سبک، سریع، schema validation و لاگ ساختاریافته داخلی؛ بدون ORM سنگین |
| DB access | درایور `pg` + SQL صریح + migration نسخه‌دار | کنترل کامل روی index/constraint/transaction؛ اجتناب از N+1 و جادوی ORM |
| DB engine | PostgreSQL 18 (تولید: مدیریت‌شده) / PGlite همان موتور در dev و CI | یک موتور، دو محیط؛ تست روی SQL واقعی نه mock حافظه‌ای |
| Frontend | React 19 + Vite + CSS اختصاصی | باندل کوچک، کنترل کامل RTL/Design System، بدون وابستگی UI سنگین |
| PWA | `vite-plugin-pwa` (Workbox) | precache کنترل‌شده + سرویس‌ورکر تولیدشده و قابل بازبینی |
| صف آفلاین | IndexedDB (`idb`) + idempotency سمت سرور | پایدار بین بستن/بازکردن برنامه، سازگار با محدودیت حجم |
| احراز هویت | کوکی opaque با هش SHA-256 در DB، رمز با `scrypt` داخلی Node | بدون وابستگی native، قابل لغو سمت سرور، مقاوم به نشت DB |
| تست | Vitest + Fastify `inject` + `@testing-library/react` + autocannon | اجراپذیر در همین محیط؛ آزمون بار واقعی |
| بسته‌بندی | npm workspaces | ساده، lock واحد، CI کوتاه |

## گزینه‌های رد‌شده

- **Prisma/Drizzle:** با PGlite سازگاری کامل ندارند و لایه انتزاعی برای SQL تحلیلی این دامنه هزینه دارد.
- **Next.js:** SSR برای سامانه‌ای که پس از ورود به‌شدت تعاملی و آفلاین‌محور است، هزینه اجرا/کش را بالا می‌برد.
- **MongoDB:** نیاز به constraint و تراکنش چندجدولی (حضور، نمره، ثبت‌نام) با مدل رابطه‌ای بهتر پاسخ می‌گیرد.
- **Keycloak/سرویس هویت جدا:** برای ۹۶۰ حساب، پیچیدگی عملیاتی توجیه ندارد.
