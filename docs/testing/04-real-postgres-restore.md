## ۱. مهاجرت و بذرپاشی روی PostgreSQL واقعی

```bash
export DATABASE_URL='postgresql://postgres:@/payesh_clean?host=/tmp/pgdata'
npx tsx src/scripts/migrate.ts   # {"ok":true,"applied":["001_core.sql","002_education.sql"],"count":2}
SEED_DEMO=1 npx tsx src/scripts/seed.ts
# {"ok":true,"students":36,"accounts":["admin",...,"guardian1..12"]}
```

`GET /api/health` → `{"status":"ok","db":"ok","migrations":2}`

## ۴. پشتیبان و بازیابی روی سرور **جداگانه**

| گام | دستور/نتیجه |
|---|---|
| پشتیبان از دیتابیس اصلی | `db:backup /tmp/backup-pg` → `{"tables":32,"rows":118211}` با sha256 هر جدول در `manifest.json` |
| سرور دوم | یک نمونه‌ی PostgreSQL دیگر با `pgdata` مستقل (`/tmp/pgdata2`) — نه همان سرور |
| بازیابی | `db:restore /tmp/backup-pg` → `{"ok":true,"tables":32,"rows":118211,"migrations":2}` |
| مقایسه‌ی شمارش | `students 66 = 66`، `attendance_records 105756 = 105756`، `grades 396 = 396`، `audit_log 8074 = 8074`، `users 59 = 59` |
| آزمون کارکردی روی دیتابیس بازیابی‌شده | سرور روی پورت ۳۳۰۰ → ورود واقعی، داشبورد با ۶۶ دانش‌آموز، صفحه‌ی حضور: **۷/۷ PASS** و صفر خطای کنسول |

نتیجه: بازیابی نه فقط «کپی فایل‌ها» بلکه یک سامانه‌ی قابل‌ورود روی سرور دیگر است.

## ۵. آنچه این سند ادعا **نمی‌کند**

- استقرار روی سرویس مدیریت‌شده (Neon/RDS/…)، TLS، پشتیبان خودکار و PITR — **NOT RUN**.
- آزمون چند‌نمونه‌ای (replica، failover، connection pooler بیرونی) — **NOT RUN**.
- اجرای هم‌زمان بار و E2E روی یک نمونه (آلودگی داده)؛ برای E2E از دیتابیس تمیز استفاده شد.
