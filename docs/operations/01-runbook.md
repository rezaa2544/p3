# عملیات و نگه‌داری

## ۱. پایش روزانه

| چه چیزی | چگونه | آستانه‌ی هشدار |
|---|---|---|
| سلامت سرویس | `GET /api/health` (هر ۱ دقیقه) | دو شکست متوالی |
| خطاهای 5xx | لاگ JSON (فیلد `res.statusCode`) | > ۱٪ درخواست‌ها در ۵ دقیقه |
| نرخ ورود ناموفق | `login_attempts` + لاگ `request rejected` | > ۵۰ در ۱۰ دقیقه از یک IP |
| صف `outbox_jobs` | `select count(*) from outbox_jobs where status='pending'` | > ۱۰۰۰ یا قدیمی‌تر از ۱۵ دقیقه |
| فضای دیسک | میزبان | > ۸۰٪ (پشتیبان‌ها بزرگ می‌شوند) |
| تأخیر داشبورد | اندازه‌گیری بار دوره‌ای | p99 > ۱ ثانیه |

> در ۰.۱.۰ داشبورد پایش/هشدار خودکار وجود ندارد؛ این‌ها دستورهای اجرایی برای تیم فنی‌اند.

## ۲. پشتیبان‌گیری

```bash
# پشتیبان متنی + manifest با sha256
# پشتیبان (مسیر پوشه به‌عنوان آرگومان اول؛ پیش‌فرض: apps/api/.data/backups/<timestamp>)
DATABASE_URL=... npm run db:backup --prefix apps/api -- /var/backups/payesh/2026-10-23

# بازیابی در پایگاه داده‌ی خالی (ابتدا سرور را متوقف کنید)
DATABASE_URL=... npm run db:restore --prefix apps/api -- /var/backups/payesh/2026-10-23
```

- **سیاست**: روزانه‌ی کامل + نگه‌داری ۳۰ نسخه + یک نسخه‌ی ماهانه تا پایان سال تحصیلی.
- **آزمون بازیابی**: ماهانه روی محیط staging؛ معیار موفقیت = تطابق شمارش ردیف‌های
  جدول‌های اصلی و باز شدن کارنامه‌ی یک دانش‌آموز نمونه.
- پشتیبان را رمزگذاری‌شده و خارج از همان سرور نگه دارید (سامانه خودش رمزگذاری نمی‌کند).

## ۳. کارهای دوره‌ای

| کار | دوره | دستور/نکته |
|---|---|---|
| پاک‌سازی کلیدهای idempotency قدیمی | ماهانه | `delete from idempotency_keys where created_at < now() - interval '30 days'` |
| پاک‌سازی نشست‌های منقضی | هفتگی | `delete from sessions where expires_at < now() - interval '7 days'` |
| بازبینی `audit_log` نمرات | ماهانه | فیلتر `action like 'grade%'` |
| بازبینی کاربران غیرفعال | هر ترم | `PATCH /api/users/:id` |
| به‌روزرسانی وابستگی‌ها | ماهانه | `npm audit --omit=dev` + `npm ci` در staging |

## ۴. رخدادها

| نشانه | اقدام اول | اقدام دوم |
|---|---|---|
| سرویس بالا نمی‌آید | لاگ `startup failed`؛ اغلب `migration … checksum mismatch` یا `DATABASE_URL` | مهاجرت جدید بنویسید؛ هرگز فایل اعمال‌شده را تغییر ندهید |
| همه‌ی درخواست‌ها ۵۰۳/خطای شبکه | وضعیت دیتابیس و پورت؛ در PGlite تک‌اتصال بودن | سرویس را دوباره راه‌اندازی کنید و صف آفلاین کاربران پس از بازگشت ارسال می‌شود |
| داده‌ی حضور ناقص | بررسی `attendance_revisions` و `audit_log` | بازیابی از پشتیبان فقط با تأیید مدیر مدرسه |
| نشست‌های مشکوک | `PATCH /api/users/:id` با `isActive:false` یا reset-password | بررسی `audit_log` و اطلاع به مدرسه |
| دیسک پر | پاک‌سازی پشتیبان‌های قدیمی و `UPLOAD_DIR` | انتقال پشتیبان به ذخیره‌ساز بیرونی |

## ۵. نگه‌داری داده

- سوابق تحصیلی (نمره/حضور): حداقل ۵ سال.
- `audit_log`: ۲ سال.
- نشست‌ها و تلاش‌های ورود: ۹۰ روز.
- فایل‌های آپلود: تا حذف مرتبط با موجودیت.
- حذف دانش‌آموز: تغییر `status` به `inactive`/`transferred` به‌جای حذف فیزیکی، برای حفظ
  یکپارچگی سوابق حضور و نمره.
